A small guide to the code

Decode the Vibe

A one-page phrase translator. A person enters a confusing phrase, chooses who they are decoding it for, and gets a plain-language meaning, likely tone, tailored rewrite, and copyable reply.

One decode, through the app

The core route is input → server-side AI request → visible result. The API key stays on the server.

1. Enter

src/main.jsx — decode(event) checks for a phrase and audience, then posts them to /api/decode.

2. Decode

api/decode.js — the handler validates both values and calls OpenAI with the server-side key.

3. Show

src/main.jsx — the response fills the meaning, tone, rewrite, and reply cards. copyReply() copies the reply.

Reference route through the source

  1. src/main.jsx — async function decode(event)Validates input and audience, manages loading/error state, and sends the request.
  2. api/decode.js — handler and client.responses.createChecks the request, reads OPENAI_API_KEY on the server, and requests the four structured fields.

To change this, start here

  • Change the audience labels in the audiences list in src/main.jsx.
  • Change what the AI explains in api/decode.js, in the instructions and resultSchema.
  • Change card wording and layout in the result section of src/main.jsx and styles in src/style.css.
  • Change the local setup instructions in README.md.

A practice to reuse

The approved journey in devpost/prd.md describes what a person should experience. The local check followed that journey: decode for two audiences, inspect the four outputs, try missing inputs, and copy a reply. On another project, trace one user action from its acceptance criteria through the code to an observable result.

Run locally with npm run dev:full after setting OPENAI_API_KEY in .env.local. Build with npm run build.
