The app in plain language

The browser handles the page and its cards. When the visitor decodes, a small Node.js function checks the phrase and audience, then asks OpenAI for the explanation. The function keeps the API key private. The page receives only the result and displays it.

Why no Express? Node.js is the server runtime. Vercel supplies the small backend function; Express would add setup for a single route without helping the first version.

What happens when someone decodes

01 · ENTERType or paste up to 500 characters.
02 · CHOOSESelect grandparent, parent, student, or coworker.
03 · CHECKBlank text or missing audience stops before any AI call.
04 · DECODEOne server request returns six predictable text fields.
05 · RESPONDRead the cards, re-decode for another audience, or copy reply.

Pieces and responsibilities

One-page interface

Phrase box, unselected audience control, field messages, loading, result cards, smooth scroll, and clipboard feedback. A new successful decode replaces the old result.

index.html · src/main.js · src/style.css

Private decode endpoint

Accepts POST JSON only; checks phrase length and allowed audience values; calls OpenAI once; returns a safe result or friendly error.

api/decode.js

Structured result

Meaning, tone, context note, when to use it, audience rewrite, suggested reply. The meaning remains the most prominent card.

Transient browser state · no database

Off-white surface, lavender and coral accents, friendly type, rounded cards, soft shadows, and comfortable mobile spacing.

Key, cost, and sharing guardrails

Keep OPENAI_API_KEY on the server, in an ignored local env file and Vercel environment settings. Do not place it in browser code or a committed file.

Use a dedicated OpenAI project, a $0.50 hard spend limit, and an alert at $0.40. Limit input to 500 characters, output to 500 tokens, and make no automatic retries. At roughly 600 input / 400 output tokens, current standard pricing estimates about $0.00026 per decode, but real usage varies.

Spend caps can take time to reflect usage and may slightly exceed the configured limit. Treat the cap as a guardrail. The deployed URL is not password protected, so share it selectively.

Failure handling

Missing input

Show the field-specific message. Send no AI request.

AI is slow or unavailable

Stop loading, keep the visitor on the page, and show a helpful error without partial results or automatic retry.

Ambiguous phrase

Explain the likely meaning and make context uncertainty visible.

Clipboard blocked

Say copying failed; leave the suggested reply visible for manual selection.

Run and demo path

Install Node.js and npm, install project dependencies, set the local OpenAI key, then run npx vercel dev. Open the local URL shown in the terminal. The exact setup commands will be added during the build.

Demo the same phrase for a grandparent and coworker, show the rewritten wording and copy action, then show validation for a missing input. Build and test locally before deploying. A public GitHub repository and short demo video are also part of the hackathon submission; the optional live URL complements them.

Decisions clarified

Backend question: A backend is required to protect the API key. Node.js is the runtime, Vercel Function is the backend endpoint, and Express is an optional web framework that is unnecessary for this one-route version.

Phrase size: 500 characters is about 70–90 typical English words, though word length varies.

Open for the build: confirm exact dependency versions and Vercel function layout early; choose the tagline during visual implementation.
